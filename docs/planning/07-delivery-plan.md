# 7. 开发任务、依赖、交付物与验收

本轮只排任务，不开始实现。任务完成的定义是验收标准通过，而不是「页面能打开」。

带 Q 编号的阻塞项见第 9 篇。阻塞项未答复时，只允许做不依赖该答案的任务；不允许用临时常数假装已经确认。

## 7.1 依赖关系

```text
T0 审查并确认阻塞项
  ├─ Q3、Q2 阻塞 T6、T7 的真实供应商接入（不阻塞假的适配器测试）
  ├─ Q4、Q15 阻塞 T3 的最终权限与会话参数
  ├─ Q5 阻塞 T11 的利润计算验收
  └─ Q8、Q7 阻塞 T13 的交付与审核细则

T1 工程骨架
  └─ T2 数据模型
       ├─ T3 认证与权限骨架
       │    └─ T4 客户、项目、成员
       │         └─ T5 素材上传
       ├─ T6 分析任务（文本）
       ├─ T8 模块模型与渲染
       ├─ T11 成本报价录入
       └─ T12 任务录入

T5 + T6 ──▸ T7 搜索选用
T6 + T7 + T8 ──▸ T9 草稿生成与模块编辑
T9 + T11 ──▸ T10 预览中的报价投影、发布快照
T10 ──▸ T13 审核与分享
T12 可与 T10 并行，但 T13 送审页要能看到任务状态
T3 ──▸ T14 审计（贯穿 T4 之后每个写接口补齐）
T10 + T13 ──▸ T15 端到端验收
T1 ──▸ T16 部署与回滚演练（可与功能并行准备，演练放在 T15 前）
```

T6 在供应商未定前，交付「适配器 + 固定夹具」，不交付生产密钥接入。

## 7.2 任务

### T0 确认阻塞项

- 依赖：无。
- 交付物：第 9 篇问题的书面答复，以及被推翻的假设列表（R-A*、D*）。
- 验收：Q1–Q8、Q10、Q12 有结论；被推翻的假设已改到对应规划文档。没有结论的项保持「未配置」，不出现伪造默认公式。
- 说明：T0 是产品确认，不是编码。本规划审查通过后才能开始 T1。T0 里尚未答复的非阻塞项不挡住 T1；阻塞项没有答复时，不开始依赖它的任务。表结构里的争议枚举等对应结论后再合并。

### T1 工程骨架

- 依赖：无。
- 交付物：TypeScript 应用入口、worker 入口、PostgreSQL、Redis、MinIO 的 Compose、空的健康检查、`.env.example`、基本 lint 与测试命令。
- 验收：本地一条命令能启动依赖；web 与 worker 进程能启动；仓库中没有密钥；`src/server` 不被客户端组件引用（用工程约束检查）。
- 不做：业务页面。

### T2 数据模型

- 依赖：T1。
- 交付物：第 5 篇各表的迁移。状态和角色枚举若 T0 未完成，先只建 T0 已确认的子集，或使用文档中的假设并在迁移说明里标注「待 T0 复核」。更稳妥的做法是 T0 完成后再合并 T2。
- 验收：迁移可在空库执行；金额列为 numeric；快照表没有更新业务内容的设计（没有把草稿和快照合成一行反复改）。
- 不做：种子报价科目。

### T3 认证与权限骨架

- 依赖：T2；最终矩阵依赖 T0 的 Q4、Q15。
- 交付物：开通方式按 Q12、登录、退出、停用即失效、按能力拒绝的检查函数。
- 验收：无会话访问内部 API 被拒绝；停用后旧 Cookie 被拒绝；财务接口在无 `finance_access` 时被拒绝；客户路由不使用这套会话。
- 不做：公开注册、多因素（除非 Q12 要求）。

### T4 客户与项目

- 依赖：T3。
- 交付物：客户档案、项目、需求正文、成员、归档、项目列表与概览页。
- 验收：符合 M3、M4、M5。隔离规则与 Q4 结论一致，并有一条反例测试（不该看见的人看不见）。

### T5 素材上传

- 依赖：T4；允许类型依赖 Q10。
- 交付物：上传、列表、预览或下载、删除保护的接口和页面。
- 验收：符合 M6；路径不由文件名决定；超限拒绝；对象不可被公开列举。

### T6 需求分析

- 依赖：T2、T5（素材元数据）；真实供应商依赖 Q2。
- 交付物：模型适配器、分析任务、结构校验、分析页的改正与确认。
- 验收：符合 M7、M8；校验失败不写当前分析；重试不删除素材；关闭素材出域时请求体不含文件二进制（用测试夹具断言）。
- 不做：让模型填写对外金额。

### T7 搜索与选用

- 依赖：T6 的已确认分析（检索词可以人工输入，因此分析失败时仍可手工搜）；真实供应商依赖 Q3。
- 交付物：搜索适配器、候选列表、选用、弃用、手工补链、来源与授权状态。
- 验收：符合 M9–M12；未选用候选不会出现在渲染输入里（用渲染函数的单元测试证明）。

### T8 模块模型与渲染器

- 依赖：T2。可与 T6、T7 并行。
- 交付物：`src/proposal` 的类型、校验、消毒、HTML 渲染。七类已确认模块加上审查保留的封面与需求理解。
- 验收：给定夹具 JSON，输出包含对应章节；输入中即使夹带成本字段也不出现在 HTML；脚本标签被去掉；报价章节只渲染传入的对客行。
- 不做：视觉定稿。先使用可读的专业排版，品牌色等 Q16。

### T9 编辑与草稿生成

- 依赖：T6、T7、T8。
- 交付物：生成草稿任务、编辑页、排序、显隐、替换案例、单模块重生成后的确认写回、乐观锁。
- 验收：符合 M13–M15；已有草稿不会被生成任务自动覆盖；冲突保存失败；替换时只能选已选用案例或本项目客户素材。

### T10 预览与发布

- 依赖：T9、T11 的报价读取（报价可以为空）。
- 交付物：预览、发布、快照列表、冻结 HTML 文件。
- 验收：符合 M16、M17；发布后改草稿，快照 HTML 字节不变；发布失败不出现可交付快照。

### T11 成本与报价

- 依赖：T2、T3。利润公式依赖 Q5。
- 交付物：成本项与报价项的录入、对客可见开关、利润接口。
- 验收：符合 M19–M21；无公式时利润为未配置且 HTTP 成功返回该状态（不是 500，也不是一个假百分比）；无财务权限为 403；分享渲染测试不含成本备注。
- 不做：税率、折扣审批、合同价。除非 Q5 把它们定义进来。

### T12 执行任务

- 依赖：T4。与提案的关联在快照存在后补上 snapshot_id。
- 交付物：手工任务、建议任务、确认与取消。
- 验收：符合 M22；重新建议不删除 `confirmed` 任务；客户 HTML 不含任务。

### T13 审核与交付

- 依赖：T10、T3；细则依赖 Q7、Q8。
- 交付物：送审、通过、退回、分享、撤销、客户阅读页。
- 验收：符合 M18、M23、R6；未通过不能交付；草稿变化后旧通过记录不能交付新内容；撤销或过期后阅读页 404；阅读页响应不含内部字段。

### T14 审计

- 依赖：T3，并在 T4–T13 的写操作上补调用。
- 交付物：审计表写入与项目内查询。
- 验收：符合 M24；抽查发布、退回、改报价、停用账号四条记录包含操作者、时间、对象；记录中无令牌明文和密钥。

### T15 主路径验收

- 依赖：T5–T14。
- 交付物：第 8 篇所列端到端用例在测试环境通过的记录。
- 验收：用测试夹具走通第 3 篇主流程；并至少覆盖：搜索为空仍能发布、模型返回非法 JSON、审核退回、交付后修改必须新版本、无财务权限、分享页隔离。
- 供应商若仍不可用，T15 对分析与搜索使用夹具，不把夹具称为已上线的全网搜索。

### T16 部署与回滚演练

- 依赖：T1；完整演练依赖 T15 的构建产物。
- 交付物：按第 8 篇部署的说明、环境清单、一次在预发环境的备份与回滚记录。
- 验收：回滚应用版本后，已发布快照仍可打开；失败的迁移不会部分暴露给流量（见第 8 篇）。

## 7.3 建议的实现顺序

1. 先完成规划审查。通过后开始 T1。阻塞项有结论的部分可以进入对应任务；没有结论的，该任务保持等待。T2 只在相关枚举已确认时合并那些列。
2. T8 提前做。渲染器是核心交付物，用夹具就能验收，不依赖供应商。
3. T3、T4、T5 打通内部录入。
4. T11、T12 用手工数据打通，利润保持未配置直到 Q5。
5. T6、T7 先夹具、后真实供应商。
6. T9、T10、T13、T14。
7. T15、T16。

不建议的顺序：先做登录页和视觉，最后才做模块渲染。那会把风险留在已确认的核心交付物上。
