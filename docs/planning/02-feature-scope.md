# 2. 功能清单

划分原则：

- MVP 只覆盖已确认主路径：录入、分析、搜索选用、模块化 HTML、编辑预览、成本利润、任务、审核交付。
- 依赖未确认业务规则的能力，MVP 只做「人能填、系统能存、确认公式后再算」，不预填行业规则。
- 会显著扩大权限、合规或运行复杂度的能力，放进第二阶段或暂不开发。

## 2.1 MVP 必须功能

### 账号与项目

| ID | 功能 | 说明 | 验收口径 |
| --- | --- | --- | --- |
| M1 | 内部登录与退出 | 仅已开通账号可登录，无公开注册 | 未登录不能进内部页面；错误口令不进入系统 |
| M2 | 账号停用 | 管理员可停用账号 | 停用后旧会话不可继续访问内部数据 |
| M3 | 客户档案 | 记录客户或品牌，供项目引用 | 可建档、可被项目关联；字段以第 5 篇最小集为准，扩展字段待确认 |
| M4 | 项目 | 一个客户需求对应一个项目，承载后续全部产出 | 可创建、打开、更新需求正文、归档 |
| M5 | 项目成员 | 记录谁参与该项目 | 成员能否决定可见范围，等 Q4；在此之前成员表先用于责任人，不额外发明隔离规则 |

### 素材与分析

| ID | 功能 | 说明 | 验收口径 |
| --- | --- | --- | --- |
| M6 | 客户素材上传 | 上传客户提供的图片、视频和文档 | 上传后可预览或下载；类型和大小上限等 Q10，超限拒绝并说明原因 |
| M7 | AI 需求分析 | 把需求正文和素材元数据变成结构化分析 | 输出符合约定结构；结构校验失败则任务失败，不写入半截分析 |
| M8 | 人工确认分析 | 编辑可改正分析并确认当前版 | 提案生成使用已确认的分析版；未确认时给出明确状态，不悄悄使用过期分析 |

分析结构的字段是合理假设，见第 5 篇。业务专有字段等服务目录（Q6）确认后再加，不在 MVP 里猜。

### 案例搜索与选用

| ID | 功能 | 说明 | 验收口径 |
| --- | --- | --- | --- |
| M9 | 生成检索意图 | 由已确认分析产生检索词，人可以改词再搜 | 每次检索保留查询词、时间和来源 |
| M10 | 搜索图片、视频、创意案例 | 通过已选定的搜索服务返回候选 | 不自建爬虫；供应商未确认时本功能不能上线，只能先做适配接口和假数据测试 |
| M11 | 选用、弃用、手工补链 | 候选不会自动进入提案 | 只有选用项能被模块引用；可手工粘贴一条参考链接并标明来源 |
| M12 | 来源与授权状态 | 每条案例记录来源地址和授权状态 | 授权未知时状态为「未知」，不显示成已获授权 |

### 提案 HTML

| ID | 功能 | 说明 | 验收口径 |
| --- | --- | --- | --- |
| M13 | 结构化提案草稿 | 用模块生成草稿，而不是保存一整段不可拆 HTML 作为源数据 | 已确认的七类内容都有对应模块：创意、案例、视觉风格、分镜参考、制作流程、报价、排期 |
| M14 | 模块化编辑 | 改文案、排序、显示或隐藏、替换该模块引用的素材 | 改一个模块不会把其他模块重置成重新生成的文本 |
| M15 | 单模块重新生成 | 只重做选定模块，人确认后才替换 | 取消或失败时原模块保持不变 |
| M16 | 预览 | 用与交付相同的渲染规则预览 | 预览中的报价只来自「对客可见」的报价项 |
| M17 | 发布快照 | 发布时冻结模块内容和渲染出的 HTML | 之后改草稿不影响已发布快照 |
| M18 | 分享交付 | 对已审核快照生成客户可打开的 HTML | 分享页不含成本、利润、任务、内部备注和未选用候选 |

封面和「需求理解」模块是合理假设（见第 1 篇），建议放进 MVP，因为没有它们提案不完整。若审查删掉，不影响七类已确认内容。

### 成本、利润、任务、审核

| ID | 功能 | 说明 | 验收口径 |
| --- | --- | --- | --- |
| M19 | 成本项 | 内部录入名称、数量、单价或金额、备注 | 客户分享页不可读到这些字段 |
| M20 | 报价项 | 内部录入对客报价，并选择是否进入提案 | 提案报价模块与被选中的报价项一致 |
| M21 | 利润核算 | 按已确认公式由成本合计与报价合计得出，只在内部展示 | 公式未配置前，界面标明「公式未配置」，不展示一个自造的利润率 |
| M22 | 执行任务 | 可生成草案，也可手工增删改；草案与已确认任务可区分 | 任务列表能保存负责人、状态、日期（日期可空） |
| M23 | 审核 | 对某个快照提交、通过或退回 | 未通过的快照不能创建交付；通过后草稿若再改，不能沿用旧通过记录交付新内容 |
| M24 | 审计 | 至少记录发布、审核、交付、报价变更、权限变更 | 记录包含操作者、时间和对象，管理员可按项目查看 |

### MVP 横切能力

- 异步任务状态：排队、执行中、成功、失败。失败原因对操作者可见，可重试。
- 乐观并发：保存模块或报价时校验更新时间，冲突时提示重新加载。不做实时协同。
- 空状态：没有案例、没有报价、搜索失败时，提案仍可编辑，不整页崩溃。

## 2.2 第二阶段

确认有使用需求后再做。不预先写进数据模型的必填字段。

| ID | 功能 | 放到后面的原因 |
| --- | --- | --- |
| P1 | 客户账号、批注、在线确认 | 改变身份模型和交付方式，Q1 未要求第一期 |
| P2 | 同一项目多套创意方向并列 | MVP 先把一套提案的版本链做对 |
| P3 | 按业务类型套用模块模板和任务模板 | 等 Q6 服务目录 |
| P4 | 内部历史案例库，搜索时与全网结果分列 | 需要先定义哪些作品属于公司 |
| P5 | 参考历史项目给出报价区间建议 | 只能建议，不能自动成交；需要历史数据口径 |
| P6 | 评论、@、邮件或企微/飞书通知 | 通知渠道未确认 |
| P7 | 版本差异对比 | 版本链在 MVP 已有，对比视图可后补 |
| P8 | 单个模块的高级 HTML 覆写 | 先保证结构化编辑；覆写会削弱模块替换 |
| P9 | 导出 PDF | 已确认交付物是 HTML，PDF 不是主路径 |
| P10 | 视频内容理解（抽镜头、听旁白） | 取决于模型能力、时长上限和素材是否允许出域（Q2、Q10） |
| P11 | 更细的数据权限（字段级、部门级） | 等真实组织方式，避免先做一套用不上的权限 |

## 2.3 暂不开发

| 项 | 原因 |
| --- | --- |
| 自建搜索引擎或爬虫集群 | 与可落地冲突：合规、封禁、存储和维权成本都高。搜索走商业 API |
| 训练或微调自有大模型 | 本期问题是流程和交付质量，不是模型研发 |
| 在线剪辑、非编、分镜时间轴编辑器 | 提案只引用分镜和视频案例，不生产成片 |
| 合同、开票、回款、总账 | 已确认输出止于成本利润核算，不是财务系统 |
| 完整 CRM（线索、公海、营销自动化） | 已确认起点是客户提交需求，不是获客 |
| 原生 App 或小程序 | 内部 Web 已覆盖主路径 |
| 多租户 SaaS | 已确认是本公司内部系统（若 R-A6 被推翻再重开） |
| 多人实时协同编辑 | 冲突面大。MVP 用乐观锁 |
| 把提案自动发布到客户官网或广告账户 | 没有这条需求，且权限风险高 |
| 向量数据库和相似历史方案检索 | 没有历史方案语料。有稳定档案后再评估，不提前引入 |

## 2.4 明确拒绝的实现方式

即使技术上更快，也不作为 MVP 方案：

- 用一次对话生成长文，再套一个固定 HTML 壳。这不满足模块化编辑和替换案例。
- 把模型返回的 HTML 字符串当作唯一数据源，后台用整页代码框修改。这样无法可靠替换某一个案例，也难以保证报价模块与报价表一致。
- 搜索接口返回什么就自动全部嵌进客户提案。质量、版权和「这不是本公司作品」都无法在自动步骤里保证。
