# 9. 待确认事项

审查时优先答复「阻塞」项。每一项都说明：为什么现在不能编、不答复时什么不能开工、以及规划里暂时怎么放。暂时的放法是假设或空配置，不是已经生效的制度。

## 9.1 阻塞项

### Q1 客户如何接收和反馈方案？

- 未知：只收链接，还是必须登录后批注、点击确认。
- 不能编造的原因：需求只说审核后交付客户，没有描述客户账号。
- 不答复的影响：客户门户（P1）无法判断是否要拉进第一期。
- 当前放法：MVP 按不登录的分享链接设计。若必须第一期批注，第 2、3、6 篇要先改再开发 T13。

### Q2 需求文本和素材能否发送到外部模型？

- 未知：允许的供应商、是否允许出境、视频和图片二进制能否上传、有没有已采购的账号。
- 不答复的影响：T6 不能接真实模型。分析质量也无法试。
- 当前放法：适配器预留供应商；`AI_ALLOW_ASSET_UPLOAD` 默认关闭；CI 只用夹具。

### Q3 全网搜索用哪一家，案例能怎么用？

- 未知：搜索 API、必须覆盖的站点（例如特定视频平台）、能否保存缩略图、能否把图片转存进提案、视频是外链还是下载、公司是否已有可引用的自有案例。
- 不答复的影响：T7 不能上线真实搜索。版权风险无法落地成允许列表。
- 当前放法：不自建爬虫；候选需人工选用；授权状态默认未知；视频规划为外链；不把网络结果称作公司作品（R-A2）。

### Q4 谁使用系统，谁能看全部项目和利润？

- 未知：岗位名单、是否按项目隔离、审核人能否编辑、编辑能否审核自己的方案、财务是否独立岗位。
- 不答复的影响：T3 的权限矩阵不能当作最终实现。
- 当前放法：假设角色为管理员、方案编辑、审核人，另加财务可见开关。不强制「自己不能审自己」。隔离规则两案并存，见第 6.3 节，上线前必须二选一。

### Q5 成本、报价、利润怎么算？

- 未知：币种、成本科目、人天是否计内部成本、税率及含税口径、利润公式、报价为空或利润为负时能否送审、有没有费率表。
- 不答复的影响：M21 不能验收。也不能让模型生成价格。
- 当前放法：只存储人工录入的数量、单价和行金额；无公式则利润为未配置（R-A8、R-A12）。不预置税率。

### Q6 公司实际承接哪些 AIGC 传媒业务？

- 未知：服务目录。例如短视频、平面、数字人、投放是否都做，需求里没有清单。
- 不答复的影响：不能做行业模板（P3），分析字段不能加业务专有项，任务草案只能是通用条目。
- 当前放法：分析使用第 5 篇的最小字段；任务以手工为主，建议任务使用可删除的通用条目，不绑定虚构服务线。

### Q7 审核有几级，谁算通过？

- 未知：单人即可，还是创意和报价分开审；退回意见是否有必填结构。
- 不答复的影响：T13 若做成多级会签可能做错。
- 当前放法：一个快照多条结论、以最新一条为准；结论只有通过或退回；退回意见为一段文字。不实现会签。

### Q8 交付链接的有效期、撤销和改版规则？

- 未知：是否必须过期、是否需要访问口令、改版后旧链接失效还是保留、归档项目后链接是否还在。
- 不答复的影响：交付策略不能当作业已确认。
- 当前放法：可撤销；过期时间可空；已交付快照不随草稿变化（R-A4）；旧链接继续指向旧快照。

### Q10 客户会上传什么文件？

- 未知：类型、单文件大小、是否要在线播放、是否要病毒扫描、视频要不要转码。
- 不答复的影响：上传限制不能设一个看起来合理的数字。
- 当前放法：环境变量未配置时拒绝上传。不做转码，不做在线非编。病毒扫描未要求就不引入杀毒集群；若公司有强制要求，在此补充后再加，不提前选型。

### Q12 账号从哪里来？

- 未知：本地口令是否可接受，还是必须对接公司现有的企业微信、飞书或 LDAP。
- 不答复的影响：登录实现可能整段返工。
- 当前放法：本地口令 + 管理员开通。不接社交登录。

## 9.2 不阻塞骨架，但会影响上线形态

| 编号 | 问题 | 当前放法 |
| --- | --- | --- |
| Q9 | 任务是否要跟踪进行中/完成，是否要前置依赖和工时 | 只做建议、已确认、取消，外加可空日期。不做网络图和工时汇总 |
| Q11 | 七类已确认模块是否允许从提案中删除 | 允许隐藏。是否允许删除等答复；渲染时空模块不伪造内容 |
| Q13 | 实现团队更熟悉 TypeScript 还是 Python | 默认第 4 篇的 TypeScript 单应用。若否决，在 T1 前改选型，数据与 API 仍可用 |
| Q14 | 提示词、客户素材、备份要留多久 | 不自动删除项目。审计不保存整份正文。保留周期确定前不写清除作业 |
| Q15 | 会话时长、失败锁定次数 | 变量预留。未设置则会话策略视为未配置，不自定「8 小时」之类常数，除非答复给出 |
| Q16 | 提案的品牌、logo、主色、对外公司名 | 渲染器先保证结构清楚。不编造公司名和品牌色 |
| Q17 | 部署在哪：云厂商、域名、是否已有服务器、对象存储区域 | Compose 拓扑不变。不新建 Kubernetes。region 等答复后写入部署说明 |
| Q18 | 是否已有必须继续使用的旧表格或历史方案需要导入 | 不做导入工具。若有，单列任务，不塞进 T4 |

Q15 与第 8 篇一致：未配置就明确未配置，而不是填一个未经同意的数字。T3 若因此缺少可运行的会话时长，应停在「等待 Q15」，不要为了演示自行挑选时长后当作默认制度。

## 9.3 建议在审查会上直接拍板的假设

下面每条都可以推翻。推翻时说明替代规则即可。

| 编号 | 建议 | 推翻后的影响 |
| --- | --- | --- |
| R-A1 | 网络案例人工选用后才进入提案 | 需要自动入选规则 |
| R-A2 | 网络案例标注为外部参考 | 需要自有案例的认定标准 |
| R-A3 | 成本与利润不进客户 HTML | 报价模块和权限要重做 |
| R-A4 | 改交付内容必须新版本并重新审核 | 回滚和链接策略要重做 |
| R-A7 | 金额只在报价表修改 | 编辑器可直接改价，须防止和报价表分叉 |
| R-A8 | 模型不生成对外金额 | 须先有费率表 |
| D1 | 模块 JSON 为源，HTML 为渲染结果 | 若坚持整页源码编辑，MVP 范围和安全设计都要重开 |
| D2 | 商业搜索 API，先接一家 | 若必须自建抓取，本规划的暂不开发清单不成立，需另做合规评估 |

## 9.4 答复之后怎么进入开发

1. 把推翻项改入对应文档，并在本文件记下结论日期和结论，不另起一套口径。
2. 仍未答复的阻塞项，对应任务保持不动（见第 7.1 节）。
3. 本规划审查通过后才开始 T1。T8 的渲染夹具还要等 D1 被接受。Q4、Q5、Q12、Q15 没有结论时，不开始 T3 和 T11 的对应部分。
4. 本轮不编写业务代码。
