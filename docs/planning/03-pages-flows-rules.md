# 3. 页面、流程、规则与异常

页面名称是信息架构草案，视觉稿不在本轮。路由用英文只为了以后实现时对齐，审查时以中文页面名为准。

## 3.1 页面清单

### 内部页面

| 页面 | 路由草案 | 谁用 | 主要动作 |
| --- | --- | --- | --- |
| 登录 | `/login` | 内部人员 | 登录 |
| 工作台 | `/` | 内部人员 | 看自己相关的项目、待审核、失败任务 |
| 项目列表 | `/projects` | 内部人员 | 搜索、按状态筛选、新建 |
| 新建项目 | `/projects/new` | 需求负责人 | 选或建客户，写标题和需求正文 |
| 项目概览 | `/projects/:id` | 项目成员 | 看状态、版本、下一步；进入各子区 |
| 需求与素材 | `/projects/:id/brief` | 需求负责人、编辑 | 改需求，上传、删除、预览素材 |
| 需求分析 | `/projects/:id/analysis` | 编辑 | 发起分析，改正，确认当前版，查看历史分析 |
| 案例检索 | `/projects/:id/research` | 编辑 | 改检索词，查看候选，选用、弃用、手工补链 |
| 提案编辑 | `/projects/:id/proposal` | 编辑 | 模块列表、编辑、排序、显隐、替换素材、单模块重生成、预览 |
| 成本与报价 | `/projects/:id/pricing` | 报价人员 | 成本项、报价项、是否对客展示；利润区按权限显示 |
| 执行任务 | `/projects/:id/tasks` | 编辑、需求负责人 | 生成草案，改任务，确认 |
| 审核与交付 | `/projects/:id/review` | 编辑、审核人 | 发布快照，送审，通过或退回，创建或撤销分享 |
| 快照预览 | `/projects/:id/snapshots/:version` | 审核人、编辑 | 只读查看某一已发布版本 |
| 账号管理 | `/admin/users` | 管理员 | 开通、停用、分配职责 |
| 系统设置 | `/admin/settings` | 管理员 | 查看非密钥配置是否齐备（模型名、上传限制）。密钥不在此页填写 |

工作台「和我相关」在 Q4 确认前没有过滤规则。假设是：管理员看全部，其他人看自己负责或参与的项目。这是假设，不是已确认规则。

### 客户页面

| 页面 | 路由草案 | 说明 |
| --- | --- | --- |
| 提案阅读 | `/p/:token` | 只渲染已交付快照的 HTML。无内部导航，无编辑 |

不设客户注册、客户项目列表、客户评论页。这些属于 Q1 / 第二阶段 P1。

## 3.2 主流程

系统不是不可回退的向导。前序结果过期时要标明，而不是锁死页面。

```text
登录
  → 新建或打开项目
  → 填写需求、上传素材
  → AI 分析（可失败重试）
  → 人工确认分析
  → 检索案例（可零结果）
  → 人工选用
  → 生成或更新提案草稿
  → 模块化编辑与预览
  → 填写成本与报价（利润待公式确认）
  → 整理执行任务
  → 发布快照
  → 审核
       ├─ 退回 → 继续编辑 → 重新发布 → 再审
       └─ 通过 → 创建交付链接 → 客户打开 HTML
  → 若再改：新版本，重新走发布与审核
```

### 操作步骤（主路径）

1. 需求负责人创建客户（若还没有）和项目，粘贴或写入需求，上传素材。
2. 编辑发起分析。系统把任务放入队列，页面显示进行中。
3. 成功后编辑检查结构化结果。改正事实错误后确认。未确认不能作为生成提案的输入。
4. 系统给出检索词。编辑可修改后执行搜索。候选以列表呈现，包含标题、类型、来源链接、摘要。
5. 编辑选用需要放进提案的项，弃用不相关项。也可以只使用客户素材，不选用任何网络结果。
6. 编辑生成草稿。已有草稿时，若分析或选用集合已变化，页面提示「输入已更新」，由人决定是否重新生成整稿或只重做某模块。不自动覆盖已编辑文案。
7. 编辑逐个模块修改。替换案例时，只能换成已选用案例或客户素材。
8. 报价人员填写成本与报价。把应展示的报价项标记为对客可见。
9. 编辑生成任务草案并改完，确认任务列表。任务允许在审核前继续改。
10. 编辑发布快照。发布物包含当时的模块、对客报价和渲染 HTML。
11. 审核人打开该快照。通过或退回都要留下记录。退回意见对编辑可见。
12. 通过后，需求负责人创建分享链接。客户打开的是该快照。

步骤 8 和 9 的先后在需求说明里是「先核算，后任务」。页面允许报价未完成时先起草任务，但送审前两者都要有明确状态：报价可以是「未填写」，系统不得显示成 0 元成交价，除非人明确把金额填成 0。

## 3.3 提案编辑流程

编辑页分三栏或等价布局：模块目录、当前模块编辑、预览。具体布局等视觉设计，数据上同时只保存模块，不另存一份手工 HTML。

模块在 MVP 的建议集合：

| 模块 | 依据 | 客户可见 | 编辑能力 |
| --- | --- | --- | --- |
| 封面 | 合理假设 | 是 | 标题、客户名、日期、版本号 |
| 需求理解 | 合理假设 | 是 | 改写分析摘要；不自动暴露内部备注 |
| 创意 | 已确认 | 是 | 文案 |
| 视觉风格 | 已确认 | 是 | 文案、参考图 |
| 案例 | 已确认 | 是 | 增删案例、改说明、替换素材、标注来源 |
| 分镜参考 | 已确认 | 是 | 镜头列表：画面、文案、时长说明、参考 |
| 制作流程 | 已确认 | 是 | 步骤列表 |
| 报价 | 已确认 | 是 | 只读投影对客报价项；要改数字须回报价页 |
| 排期 | 已确认 | 是 | 阶段与日期；日期可空 |

报价模块不在提案编辑器里直接改金额，避免和内部报价表分叉。这是假设 R-A7。

隐藏模块后，预览和随后的快照都不渲染它。隐藏不是删除，可再显示。

## 3.4 项目状态

状态描述的是交付进度，不是 AI 任务进度。AI 和搜索用独立任务状态。

下列状态是**合理假设**，确认前不编码。

| 状态 | 含义 |
| --- | --- |
| 草稿 | 项目已建，分析尚未确认 |
| 方案编辑中 | 分析已确认，草稿可编辑；搜索和报价可以仍未完成 |
| 待审核 | 存在一个已提交、尚未结论的快照 |
| 退回修改 | 最近一次审核是退回 |
| 审核通过 | 最近一次送审快照已通过，且草稿没有新的未发布改动需要另审 |
| 已交付 | 该通过的快照已创建有效交付 |
| 已归档 | 不再作为进行中项目；已发链接是否仍有效见 Q8 |

允许的回退：除「已归档」外，内容编辑随时可进行。一旦已通过的快照对应的草稿被修改，项目从「审核通过」或「已交付」回到「方案编辑中」，旧通过记录只对旧快照有效。已发给客户的旧链接在 Q8 确认前，按「继续指向旧快照」设计。

## 3.5 业务规则

### 已确认，实现时必须遵守

| 编号 | 规则 |
| --- | --- |
| R1 | 客户正式看到的完整方案是 HTML |
| R2 | HTML 至少能够承载创意、案例、视觉风格、分镜参考、制作流程、报价、项目排期 |
| R3 | 方案不是不可编辑的整段 AI 文本；后台按模块改文案、替换案例素材 |
| R4 | 案例来源包括客户素材，以及全网搜索得到的图片、视频、创意案例 |
| R5 | 同一业务链路包含成本利润核算和执行任务拆解 |
| R6 | 交付发生在审核之后 |

### 合理假设，审查确认前不是规则

| 编号 | 假设 |
| --- | --- |
| R-A1 | 网络候选必须人工选用后才进入客户可见模块 |
| R-A2 | 网络案例标注外部参考和来源，默认不称作公司案例 |
| R-A3 | 成本、利润、任务、分析底稿、未选用候选不对客户链接可见 |
| R-A4 | 已发布快照和已交付 HTML 不可原地改写 |
| R-A7 | 对客金额只在报价数据中修改，提案模块只投影 |
| R-A8 | 模型可以建议成本或报价的**科目名称**，不可以生成对外金额。金额只来自人工录入 |
| R-A9 | 检索、分析和生成失败不删除已有草稿、素材和已选用案例 |
| R-A10 | 送审对象是快照。审核人的结论不自动改写模块正文 |
| R-A11 | 同一项目同时只有一个提案草稿；历史靠快照保留 |
| R-A12 | 利润为负或报价为空时允许保存。是否禁止送审，等 Q5，系统先不拦截 |

R-A8 是建议，不是已确认的财务制度。它避免模型编造价格。若业务明确要求模型按费率表算金额，前提是先提供费率表和公式（Q5）。

## 3.6 异常场景

| 情况 | 系统行为 | 不做什么 |
| --- | --- | --- |
| 分析或生成超时、供应商错误、返回无法通过结构校验 | 任务标失败，保留错误摘要，允许重试 | 不把残缺 JSON 写进当前分析或模块 |
| 搜索零结果、搜索服务不可用 | 候选为空并说明原因；可手工补链或只用客户素材继续 | 不阻断保存项目 |
| 第三方图片或视频在预览中打不开 | 该案例显示来源链接和「无法加载」；编辑可替换或移除 | 不因为一条外链失败让整份提案打不开 |
| 上传类型不在允许列表，或超过大小上限 | 拒绝该文件并说明限制 | 不入库 |
| 两人同时改同一模块 | 后保存者若基于过期更新时间，保存失败并提示刷新 | 不静默覆盖对方内容；也不做实时合并 |
| 审核期间编辑又改了草稿 | 允许改草稿；正在审的仍是旧快照。通过只对那份快照生效 | 不把审核通过套到新草稿上 |
| 对已通过快照再次修改后直接点交付 | 拒绝。需要新快照和新的通过记录 | 不更新旧交付的内容 |
| 分享已撤销、已过期或令牌错误 | 客户页不返回提案内容 | 不提示该链接曾经对应哪一个客户 |
| 删除仍被模块引用的素材 | 阻止删除，或要求先从模块移除后再删。实现二选一，推荐阻止并列出引用位置 | 不留下指向空文件的客户页 |
| 删除已被报价引用的成本项 | 允许删除成本项，报价保留，关联清空，并在报价页提示 | 不自动改对客价格 |
| 公式未配置时打开利润区 | 展示成本合计与报价合计（有权可见），利润显示未配置 | 不套用 税率或默认毛利率 |
| 内部人员被停用 | 会话失效 | 不删除其历史操作记录 |
| 发布时渲染失败 | 不产生快照，草稿保持原样 | 不把半份 HTML 标成已发布 |

待确认才会改变上述行为的点：审核级数（Q7）、链接失效策略（Q8）、上传限制（Q10）、利润是否允许为负仍送审（Q5）。
