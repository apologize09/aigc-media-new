# 10. HTML 可视化编辑器基础方案

本方案说明内部人员如何改那份客户最终会看到的 HTML。它遵守已经确认的规则：模块是可编辑源数据，HTML 是渲染结果；豆包生成模块内容并自行匹配素材；报价数字本期由人工填写，且不在这个编辑器里改金额。

本篇是编辑器的基础方案，不包含页面代码。品牌色、logo 和公司名仍等 Q16，所以编辑器先使用一套中性版式，不提供换肤。

## 10.1 编辑器是什么

编辑器的主画面就是提案本身。编辑在版式上改字、换图、调整模块顺序，右侧或浮层只在纯文字放不下的时候出现。保存之后，预览、发布和客户链接使用同一个渲染函数。客户打开的页面没有编辑框、拖动手柄和内部角标。

因此它不是：

- 整页 HTML 源码编辑器。
- 可以任意拖到坐标上的自由画布。
- 把豆包返回的 HTML 字符串再套一层可视化外壳。

模块在页面上纵向排列，只能在模块与模块之间调整顺序，不能叠放，也不能改变每一块内部的栅格。内部栅格由该模块的渲染模板决定。这样替换一张案例图时，周围的文案和报价表还在原处。

## 10.2 画面结构

桌面宽度是这个编辑器的使用环境。基础方案不另做手机上的编辑布局。

```text
┌ 模块目录 ┬ 提案画布 ─────────────────────────┐
│ 封面     │ 保存状态    宽度    关闭编辑装饰   │
│ 需求理解 │                                      │
│ 创意     │   与客户 HTML 相同的纵向模块         │
│ 视觉风格 │   选中的模块显示操作条               │
│ 案例     │                                      │
│ 分镜     │                                      │
│ 制作流程 │                                      │
│ 报价     │                                      │
│ 排期     │                                      │
└──────────┴──────────────────────────────────────┘
         需要选素材、看来源或改日期时，再打开侧栏
```

- 模块目录用于跳转、排序和看隐藏状态。隐藏的模块仍留在目录里，画布上不渲染。
- 画布按客户页面的阅读顺序展示。编辑装饰画在模块外面，不写进模块 JSON，也不进入发布出的 HTML。
- 「关闭编辑装饰」仍用同一个渲染函数，只是去掉操作条，用来检查客户将会看到的样子。
- 宽度只影响画布容器，基础方案提供宽、窄两档，方便看一行里案例如何折行。这不是两套模板。
- 侧栏默认关闭。打开它的动作只有：替换素材、查看或修改来源、编辑分镜的一项、编辑排期日期。

审核人和只读快照页不加载这套编辑器。它们显示已发布 HTML。

## 10.3 每种模块在画布上怎么改

长文用 TipTap，并且只允许段落、标题、列表、加粗、斜体和链接。链接只保留 `http` 与 `https`。图片不放进 TipTap，避免正文里出现无法单独替换的图。标题、说明、日期和步骤名用画布上的短字段。从外部粘贴时，丢掉脚本、样式和 TipTap 不认识的标签。

| 模块 | 画布上直接改 | 侧栏才改 | 不能在这里改 |
| --- | --- | --- | --- |
| 封面 | 标题、客户显示名、日期 | 无 | 版本号。版本号由发布产生 |
| 需求理解 | 正文 | 无 | 内部备注。内部备注不在这个模块里 |
| 创意 | 正文 | 无 | 无 |
| 视觉风格 | 风格说明；参考图的替换和移除 | 来源名称、来源地址 | 无 |
| 案例 | 调整条目顺序，改说明，移除条目 | 替换图片、视频或创意链接；看来源和授权角标 | 把网络案例改写成公司作品 |
| 分镜参考 | 调整镜头顺序；改画面、文案、时长说明 | 为一镜选择参考图 | 把时长说明换算成工时或报价 |
| 制作流程 | 调整步骤顺序，改步骤名和说明，增删步骤 | 无 | 无 |
| 报价 | 只显示已标记为对客可见的报价行 | 无。金额、数量到报价页改 | 在画布上输入单价或总价 |
| 排期 | 调整阶段顺序，改阶段名和说明 | 开始日期、结束日期，均可空 | 用任务页的日期自动覆盖这里 |

案例和视觉风格里，授权状态只出现在编辑器角标上，例如「客户提供」「未知」「已授权」。客户 HTML 显示来源名称和来源地址，不显示这枚内部角标。网络来源保持为外部参考。

转存还没成功的案例可以留在画布上，并标出失败原因。发布时，这种只有媒体、没有成功副本的条目不能进入快照。只有标题和来源、本来就没有媒体文件的创意参考可以发布。

报价模块在没有对客报价行时，画布显示「尚未填写对客报价」，不显示 0 元。

## 10.4 素材替换

替换时只列出三类来源：

1. 本项目客户上传的素材。
2. 豆包本次 `web_search` 已经转存成功的副本。
3. 编辑手工补上的链接。补链后走同一套转存；限制未配置或地址无法下载时，替换不成功，原素材保持不变。

选择一张已转存的图或一段已转存的视频后，模块记录素材 ID。画布立即改用这份副本。客户页面不使用供应商的临时地址，也不使用永久公开的存储地址；发布后的 HTML 使用绑定该快照的访问方式。

不能从编辑器把任意网页抓进服务器。手工补链只提交一个地址，由 worker 按已定的转存限制下载。

## 10.5 单模块重新生成

每个模块的操作条上有「重新生成」。它只把这一块交给豆包，并可以再次使用 `web_search`。

- 生成过程中，画布上的原文保持可编辑，不被加载状态替换掉。
- 任务完成后，在该模块下方并排显示新结果，由人选择「采用」或「放弃」。
- 放弃或任务失败时，模块 JSON 不变。
- 采用时整块替换这一模块的内容，并用当时的 `updated_at` 做乐观锁。其他模块不动。
- 报价模块不提供重新生成，避免模型写入金额。

整稿再次生成也遵守同一条：已有草稿时不自动覆盖。编辑器在工具条上提示「分析或素材已更新」，人明确选择后才整稿替换。

## 10.6 保存与两人同时编辑

输入先留在浏览器里。发生模块失焦或使用保存时，才提交这一模块的内容和当时读到的 `updated_at`。不在每次按键时请求服务器。

保存成功后，目录上的未保存标记消失。保存失败时，浏览器里的修改还在，并说明原因。若服务器上的 `updated_at` 已经变了，提示刷新后再改，不用后来的内容盖掉前一个人的保存。基础方案不做实时协同，也不自动合并两份正文。

隐藏、排序和删除一条案例，同样各自提交，并带上乐观锁。排序提交的是新的顺序，不是整份提案文档。

## 10.7 从编辑器到客户 HTML

```text
画布上的修改
    → 模块 JSON
    → 渲染函数（不含编辑装饰）
    → 预览
    → 发布时写入对象存储中的 HTML 文件
    → 审核通过后，链接只读这份文件
```

渲染函数的入参只有模块、对客报价行、客户显示名、版本号和可公开的素材信息。编辑器即使本地状态里暂存了成本或利润，也不能把这些字段传给渲染函数。

发布读取的是服务器上已保存的模块。画布上还有未保存修改时，发布按钮不可用，并指出哪一个模块还没保存。

## 10.8 基础方案不做的事

| 不做 | 原因 |
| --- | --- |
| 自由定位、图层和任意栅格 | 无法稳定替换某一张案例，也会让两次渲染对不上 |
| 模块自定义 CSS、字体和颜色面板 | 品牌尚未确认。中性模板先保证结构 |
| 整页或单模块 HTML 源码覆写 | 已放在第二阶段。基础方案一旦允许，模块替换就失效 |
| 在 TipTap 里插图表格 | 图属于素材字段，报价和排期是结构化模块 |
| 报价画布内改价 | 避免和报价页分叉。这是 R-A7，仍可推翻 |
| 删除整个已确认模块 | Q11 未答复。基础方案只允许隐藏。案例条目、镜头和步骤可以删除 |
| 实时多人光标 | 本期用乐观锁 |
| 手机编辑布局 | 内部人员以桌面使用为准。客户阅读页仍按发布出的 HTML 显示 |
| 编辑器内剪辑视频或绘制分镜 | 只选择已有参考，不生产成片 |

## 10.9 实现时的边界

开工后按下表拆分。本篇不创建这些文件。

```text
src/proposal/            模块类型、Zod、无编辑装饰的渲染
src/components/editor/   目录、画布、操作条、TipTap、素材选择
```

`src/proposal` 不引用编辑器组件。发布和客户链接只调用渲染函数。编辑器组件可以调用渲染函数，再在外面加上操作条。

验收时至少看这几条：

1. 改创意正文并保存后，关闭编辑装饰的画面与发布 HTML 中的该段文字一致。
2. 替换案例只改变这一条素材，其他模块的文字保持不变。
3. 报价画布上不能输入金额；报价页改完并标为对客可见后，画布和发布 HTML 同时出现该行。
4. 重新生成选择放弃后，原模块内容还在。
5. 用过期的 `updated_at` 保存会被拒绝，浏览器里未保存的文字不丢失。
6. 发布出的 HTML 不含操作条、授权角标、成本、利润和任务。
